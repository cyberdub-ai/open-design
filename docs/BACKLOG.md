## A. Регрессии: поведение форка исчезло из дерева

1. **`OD_MCP_READONLY` / `WRITES_ENABLED` (из `e58fc262cf`) отсутствует полностью.**
   Все пишущие MCP-тулы регистрируются безусловно (`apps/daemon/src/mcp.ts`, `TOOL_DEFS`).
   Намерение оператора «только чтение» сейчас нечем выразить. Чинить с красным тестом:
   при `OD_MCP_READONLY=1` `localMcpToolDefinitions()` не содержит пишущих тулов.
2. ~~**`OD_EXTRA_ORIGINS`**~~ — ЗАКРЫТО 05.09, кода не требует. Форковый коммит `78cdef47d1`
   (а не `944fe8756e`, как значилось в инвентаризации) просто подмешивал строки в набор
   разрешённых origin. Апстримный `OD_ALLOWED_ORIGINS` делает то же строже: разбирает URL,
   отбивает не-http(s), нормализует origin (`apps/daemon/src/origin-validation.ts`). Это
   вытеснение, а не потеря, и прод на него уже переехал:
   `open-design.service` несёт `OD_ALLOWED_ORIGINS=https://open-design.cyberdub.su`.
   Возвращать форковое имя незачем — оно было бы вторым способом сказать то же самое.
3. ~~**`--skip-discovery` в CLI никогда не был реализован**~~ — ЗАКРЫТО 05.09, коммит
   `c763b2b93e`. Заявку сделал форковый коммит `78cdef47d1` (в инвентаризации стоял
   неверный `944fe8756e`), но `cli.ts` он не трогал вовсе. Реализовано: флаг зарегистрирован
   в `PROJECT_BOOLEAN_FLAGS` (без этого `parseFlags` отбивает его как неизвестный),
   описан в help и кладёт `skipDiscoveryBrief: true` в тело `POST /api/projects` только
   когда его попросили. Веб-поверхности нет намеренно — это то самое исключение из правила
   двойной поверхности: UI собирает бриф интерактивно, а флаг существует ровно для
   автоматических прогонов, где отвечать некому.
   Проверено так: `pnpm exec vitest run tests/cli-project-create-discovery.test.ts` → 3 passed
   (2 из 3 были красными до правки).
